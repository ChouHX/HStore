## 支付宝金额向上取整 + USDT 至少 1 USDT

### 支付宝：不足 1 分向上取整
- 原来 `math.Round(amount*100)` 会把 0.064 变成 0.06（比售价还低）。
- 改为 `service.ceilToCents()`：先 Round 再判断余量 > 1e-6 才 +1。
  **不能直接 math.Ceil**：0.06*100 在 float64 里是 6.000000000000001，Ceil 会多收 1 分。
- 前端 `lib/format.ts` 也有同名的 `ceilToCents`，弹窗应付金额同步显示 0.07 并提示换算。

### USDT：自动把数量提到 ≥ 1 USDT
- `service.MinUsdtCountForGuest(unitPrice, rate) = ceil(rate / unitPrice)`；
  例：单价 ¥6、汇率 7.2 → 至少 2 件。
- `CreateGuestPurchase` 在 usdt 分支里自动改写 count 并重算金额；
  超出限购/库存则报错提示改用支付宝。
- 弹窗切到 USDT 时自动把数量输入框下限抬到 `usdtMinCount`，并提示「已自动调整数量」。
- `guest_price_test.go` 覆盖 0.064/0.06/0.192 与 6/7.2、0.064/7.2 等边界。

## 全站卡死排查（SIGQUIT 抓栈）+ 一批后台调整（commit ff91bfc / 2df1d5d）

### 卡死根因（重要）
线上现象：`/api/health` 秒回，但 `/api/store/home`、`/api/goods/detail`、`/api/alipay/config`
全部挂死 30–60s 以上；浏览器 6 个连接被占满 → 整站「打不开」。

排查手法：`docker kill -s QUIT hstore` 让 Go dump 全部 goroutine，
`docker logs hstore > /tmp/stack.txt 2>&1`（注意顺序！`2>&1 >` 会把 stderr 丢到终端）。
栈里几十个 goroutine 全堵在 `database/sql.(*DB).conn`，但**没有任何 goroutine 持有连接** —— 
说明连接被某次请求拿走后再也没还回来。

修复：`SetMaxOpenConns(1)` → `4` + `MaxIdleConns(4)` + `ConnMaxLifetime(30m)`。
单连接模式下「一条连接卡住 = 全站 DB 全挂」，这是架构级放大器，必须先拆掉。
（写并发靠 busy_timeout(10000) 串行化。）

## 商品详情本地缓存（同步时落库，接口直读）

### 起因
`/api/goods/detail` 每次都实时调上游 `getDetail`，要过一遍 WAF 挑战，实测 0.7s+。

### 方案
- `products` 新增 `detail_json TEXT` / `detail_synced_at INTEGER`（addColumns 迁移 + 建表语句同步）。
- **缓存存上游原始 JSON，不存解析后的结构体**。`upstream.GetDetailRaw()` 返回 `json.RawMessage`，
  `GetDetail()` 解析结构体后顺手 `store.SaveProductDetail()`。
  这样所有已有的同步路径（`SyncFromRemote` → `enrichStock`、`RefreshProducts`、
  `EnrichImportedStock`、`RefreshStockForProducts`、`FetchStockCounts`）**自动变成写缓存**，
  调用点一行没改。
- `upstream.DetailCached()`（`detail_cache.go`）：读本地缓存；超过 `DetailCacheTTL`(10min)
  就 `refreshDetailAsync()` 后台刷新，当前请求仍返回旧缓存（stale-while-revalidate）；
  只有从没同步过的新商品才同步回源一次。后台刷新按 goodsID 去重。
- `handleGoodsDetail` 改为 `DetailCached` + `withLocalStock()`：
  用本地 `stock_count` 覆盖缓存里的旧库存（本地由 60 秒节流刷新，比 10 分钟 TTL 新）。
  `withLocalStock` 用 `json.Decoder.UseNumber()`，否则 float64 往返会把
  `9007199254740993` 变成 `9007199254740992`、`6.1234` 可能变科学计数法。
- `SyncFromRemote` 是「先删后插」，DELETE 前把 `goods_id → detail_json` 快照到内存，
  INSERT 时带回（`CASE WHEN excluded.detail_json<>''` 兜底），避免一次同步把缓存全清空。

### 顺带修掉一个真 bug
`model.GoodsDetail` 之前只声明了 `RemoteProduct + min/maxQuantity`，
上游的 `goodsDescribe` / `goodsDetail` / `buyNotice` / `rechargeTemplates` / `goodsTags` /
`serviceTags` / `limitBalance` **全部被反序列化丢掉** —— 线上实测接口返回里根本没有这些 key，
所以购买弹窗的「商品详情 / 购买须知 / 充值模板表单」一直是空的。
现在结构体补齐（复杂结构用 `json.RawMessage` 原样承接），且商详接口直接返回缓存原始 JSON，
上游以后加字段也不会再丢。

### 测试
- `product_detail_test.go`：缓存原样读回、新鲜/过期判定、超长截断（512KB）、空内容不清缓存。
- 顺手修了 `alipay_test.go` 的 Windows 问题：`db.Open()` 是 `sync.Once` 单例，
  测试里 `t.Setenv` 到 `t.TempDir()` 无效且会导致 TempDir 清理失败（连接池占着文件）。
  改成 TestMain 里 `db.Open()` + `m.Run()` + 新增的 `db.Close()` + RemoveAll。
- 本地实测（假上游配置，缓存命中就不该发请求）：命中 **1.0–1.2ms**；
  过期 20 分钟仍返回旧缓存（后台刷新失败不影响）；清空缓存后才会回源并报网络错误。
